# 기술 명세

## 1. 기술 스택

### 선택 기준
- 서버 없이 API 키 보안 유지 가능
- Google OAuth + YouTube Music 연동 용이
- MVP 이후 커뮤니티·랭킹 확장 가능한 DB 구조
- 무료 티어로 MVP 운영 가능

### 확정 스택

| 영역 | 기술 | 이유 |
|------|------|------|
| 프레임워크 | **Next.js (React)** | Serverless API Routes 내장, SEO 대응, Vercel 배포 최적화 |
| 스타일링 | **Tailwind CSS** | 모바일 우선 빠른 구현, 다크 모드 지원 |
| 인증 | **NextAuth.js** (Google Provider) | Google OAuth 처리 간소화, 세션 관리 포함 |
| 데이터베이스 | **Supabase** (PostgreSQL) | 무료 티어, 향후 커뮤니티·랭킹 확장 적합, REST·Realtime API 제공 |
| 배포 | **Vercel** | Next.js 최적화, Serverless Functions 무료 제공 |
| 폰트 | **Pretendard** | CDN 웹폰트, 한국어·영문·숫자 단일 적용 |

### API 키 보안
- YouTube API 키, Spotify API 키는 **Next.js API Routes (serverless function)** 안에서만 호출
- 클라이언트에 키 노출 없음 — 환경변수 `.env.local`로 관리

## 2. 추천 알고리즘

### 구조
YouTube + Spotify 하이브리드 방식. YouTube로 후보 곡을 수집하고 Spotify `audio-features`로 감정 정확도를 높임.

```
설문 입력 → 키워드 조합 → YouTube search.list → 후보 20~30곡
                                                        ↓
                                          Spotify search → track_id 획득
                                                        ↓
                                          Spotify audio-features 조회
                                          (valence, energy, tempo)
                                                        ↓
                                          컨디션 범위 필터링 → 최종 10곡

※ Spotify 매칭 실패 시: 해당 곡 필터 제외하고 유지 (fallback)
※ Spotify API 전체 실패 시: YouTube 상위 10곡 그대로 반환 (fallback)
```

---

### 항목별 처리 방식

#### 감정 선택지 — GEMS 기반 (Geneva Emotional Music Scales)

음악 감상 감정에 특화된 표준 체계. 9개 계열에서 서비스에 맞게 선별·한국어화.

| 감정 | GEMS 계열 | Spotify 키워드 | YouTube 검색 키워드 |
|------|----------|--------------|-------------------|
| 설렘 | Joyful Activation | happy upbeat | exciting romantic upbeat |
| 신남 | Joyful Activation | energetic dance | energetic hype party |
| 평온함 | Peacefulness | calm relaxed | calm peaceful relaxing |
| 집중 | Tension (low) | focused study | focus study concentration |
| 따뜻함 | Tenderness | tender warm | warm cozy acoustic |
| 향수 | Nostalgia | nostalgic | nostalgic retro classic |
| 강렬함 | Power | powerful | intense powerful anthem |
| 우울함 | Sadness | sad melancholy | sad melancholy emotional |
| 경이로움 | Wonder | dreamy | dreamy ethereal ambient |

> 복수 선택 시 키워드를 이어 붙여 검색

#### 컨디션 슬라이더 → Spotify `valence` + `energy` 필터

**UI 정의**
- 9단계 슬라이더 (1~9)
- 왼쪽 레이블: "우울한" / 중간 레이블: "무난한" / 오른쪽 레이블: "행복한"
- 드래그로 단계 이동

**알고리즘 매핑**

슬라이더 위치가 Spotify `valence`(감정 긍정도: 0.0~1.0)와 `energy`(에너지: 0.0~1.0)에 직접 대응.

| 단계 | valence 범위 | energy 범위 | 설명 |
|------|------------|------------|------|
| 1~3 (우울한) | 0.0 ~ 0.35 | 0.0 ~ 0.4 | 감정적·느린 곡 |
| 4~6 (무난한) | 0.3 ~ 0.65 | 0.3 ~ 0.65 | 중간 에너지 |
| 7~9 (행복한) | 0.6 ~ 1.0 | 0.55 ~ 1.0 | 밝고 에너지 높은 곡 |

> 컨디션 미선택 시: valence·energy 필터 미적용, YouTube 결과 상위 10곡 사용

---

#### 전체 미선택 시
- YouTube `chart=mostPopular`, `regionCode=US`, `videoCategoryId=10`으로 빌보드 기준 인기곡 10곡 반환

## 3. 공유 URL 구조

### 방식
- **정식**: Supabase DB 저장 기반 고유 UUID URL
- **테스트**: 쿼리 파라미터 인코딩 (DB 없이 빠른 확인용)

### DB 스키마 (Supabase)

**`playlists` 테이블**

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | UUID (PK) | 공유 URL에 사용되는 고유 ID |
| `user_id` | UUID (nullable) | 로그인 사용자 연결, 비로그인 시 null |
| `survey_data` | JSONB | 설문 입력값 전체 (감정·컨디션·분위기·장르·국가) |
| `tracks` | JSONB | 추천 곡 배열 (track_id, title, artist, thumbnail_url, youtube_url) |
| `created_at` | TIMESTAMP | 생성 시각 |

**공유 URL 형식**: `/playlist/[uuid]`

### 테스트용 파라미터 URL

```
/playlist?emotion=설렘,신남&condition=7&mood=드라이브&genre=팝,EDM&country=미국
```

- 동일한 추천 로직 실행 → 결과 화면 렌더링
- 매번 동일한 10곡 보장 안 됨 (랜덤성) — 테스트 목적으로만 허용

## 4. 외부 API 정리

| API | 용도 | 무료 한도 |
|-----|------|---------|
| YouTube Data API v3 | 곡 검색, 플레이리스트 저장 | 10,000 units/일 (search 1회 = 100 units) |
| Spotify Web API | valence·energy·tempo 조회 | 무제한 (rate limit 있음) |
| Google OAuth 2.0 | 구글 로그인 | 무제한 |
| Supabase | DB (플레이리스트 저장) | 무료 500MB, 50,000 MAU |

> YouTube API: 1일 100회 검색 가능 → MVP 충분. 사용자 증가 시 쿼터 상향 신청.
